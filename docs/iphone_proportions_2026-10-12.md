# Phone control proportions — 2026-10-12

The owner reported that the new icon HUD still felt bulky and cramped on iPhone, with inconsistent button proportions. This pass refines the existing controls and their screen scaling. It does not change maps, resource rates, AI decisions, prices, combat strength, objective durations or victory rules.

## Starting point

The checked-out baseline is documentation commit `b8ebfac`, following the published beta.4 runtime `25fd059ed176c4b01f3eec1594e1cc4a574894e3`. Its clean source SHA-256 is `01803f3d63aea821937696431119a4ec9de745b706c5cc340dc3e51b24ac4616`; the recorded public release is `releases/25fd059ed176-20261012-icons`. Those historical publication and gameplay receipts are in [the icon HUD pass](icon_hud_pass_2026-10-12.md). They are not validation of this new source.

The beta.4 Build screenshots showed category buttons stretched to roughly 185×48, with icons separated from centered captions. The sole Defence card stretched across its row. The same family mixed tall captioned commands, broad management launchers and a duplicate selected-worker job strip.

A native screen-scaling diagnostic also found that an authored 48-logical-pixel target could render at about 37.9 screen units on a 667-wide window. Logical minimum-size assertions alone therefore do not establish browser touch dimensions. This diagnostic modeled Web canvas dimensions using native Godot; it was not a physical iPhone or a browser DPR measurement. Its receipts remain under `output/evolution/iphone-proportions-20261012/physical-web-canvas-20261012T233523Z-f6a554/`.

## Source changes

- Shared command metrics are 48 logical pixels per primary target, 24-pixel glyphs, six-pixel spacing and six-pixel button corners. The dock and management panels use eight-pixel corners. Captioned expanded commands place the icon beside the caption instead of stacking them into a tall control.
- The field dock uses 64 logical pixels for simple selections, expanding to 72 when cargo or counter detail needs a second line. Paid building production retains its 72-pixel allowance for portraits, names, costs and Repeat state. Management launchers are square 48-pixel targets. The duplicate worker job strip is removed from the field dock; exact assignments remain in Economy.
- Build category tabs size to their icon and caption as a group. A flexible separator places Again, Info and Close together on the right. Cards consistently request 150×80, including Defence, with unchanged 13-pixel text and reduced vertical padding. Costs, age locks, shortages and Farm's 300 finite food remain on the cards. The sheet uses a lighter shadow and reserves safe-area margins. Rendered text fit and actual dimensions still require final checks.
- Economy job choices adapt between 80 and 96 logical pixels. Producer action controls adapt to available width, approximately 110–120 pixels on the intended phone layouts. Producer recruitment retains names, portraits and every numerical cost. Sheets remain exclusive and keep their launchers reachable; stable producer identity, payments, population reservations, refunds and Repeat behavior remain the existing mechanisms.
- Display scaling now calculates an automatic floor intended to keep an authored 48-pixel target at least 44 screen pixels at Normal interface size. The saved interface-size preference multiplies that floor. Web calculations use the CSS size of the safe-area-adjusted game element rather than Retina backing pixels or raw device-pixel ratio. Resize handling reapplies the calculation without replacing the user's saved preference.
- Below 650 logical pixels, resources use a two-column grid with unchanged 14-pixel text. Population shares its line with the Age numeral; its full age name remains accessible. Age Up keeps its full costs in a narrower button. This prevents the automatic target floor from pushing the resource rail or production controls off the smaller screen.
- Cold native import exposed a Godot 4.6 threaded font-import crash. The project now disables parallel editor imports; this does not change match simulation. The failed import receipt is retained, and subsequent stages must complete a clean import.

The welcome page, installation guidance, release notes, private reports and safe Main Menu update boundary remain part of release acceptance. The larger-map pacing limitations documented in [the map pass](large_maps_pacing_2026-10-12.md) remain unchanged; presentation work does not establish typical 8–15 minute matches.

## Validation status

The latest relevant runs pass for nine native suites and seven headless suites, across immutable staged snapshots. They cover composition, readability, exclusive sheets, paid production, Strategy, Build, pointer/touch routing, camera centering and display scaling. Subsequent fixes received focused reruns; this is not a full-suite rerun on one final snapshot. Exact source deltas and retained failures are recorded in `output/evolution/iphone-proportions-20261012/final-validation-coverage.json`. The final caption source also passes 52 Python tests, 19 Web tests, JavaScript syntax and release-notes JSON checks. Clean export, browser gameplay and publication acceptance remain pending.

The first native diagnostic caught a missing Strategy attachment in the standalone composition fixture, clipped two-resource Build shortage text, one-pixel Army scroll clipping at Medium UI size, and narrow Economy producer captions enlarging their panel. Corrections attach the same Strategy component as a real match, wrap the complete shortage/action captions and reserve two pixels for Army layout rounding. Assertions remain strict; the failed receipts are retained. The new narrow resource grid also responds to an observed clipped Food counter, rather than assuming that a logical minimum implies a comfortable screen target.

Acceptance must distinguish native Godot rendering from actual Web rendering. The target matrix includes 844×390 and 932×430, plus the smaller 667×375 profile, all three interface sizes and ordinary/notched safe areas. Native diagnostics can expose minimum-size and containment defects; browser checks must also inspect CSS canvas dimensions and dispatched controls after scaling. The final clean artifact still needs ordinary paid Easy and Medium matches, visibly verified seeds, meaningful 1× openings, natural endings and matching report identities.

No physical iPhone or installed Pocket Kingdoms PWA is available for this pass. Desktop touch emulation and native window probes do not establish thumb comfort, physical safe-area behavior, installed-PWA lifecycle, subjective audio or sustained phone performance.
